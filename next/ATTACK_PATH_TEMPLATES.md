# 攻击路径模板与拓扑候选

在「攻击路径」步骤中新增或编辑路径，点击「从预置模板添加」。可按分类和关键词查找，查看当前资产的匹配线索，再展开入口、攻击前提、有序步骤、攻击目标和待核对控制。选中后仅加入当前表单，保存风险场景才写入项目。

## 使用原则

预置模板适用于汽车、工业设备、物联网、云服务及其他软硬件系统的初步分析。每条模板定义入口、适用前提、攻击步骤、目标与控制检查项；采用后需结合实际项目核实。

- 匹配线索根据资产关联、实体类型、操作系统、协议和安全属性产生。没有完整上下文时仍能浏览全部模板；未被推荐不代表不适用。
- 采用后是独立、可编辑的项目路径。应改写成实际入口、组件、访问条件与目标，不把模板当作已完成评估。
- 新路径的可行性为待评估；五因子潜力、风险评分、验证结果和风险接受不会自动填写。既有路径和评分保持原样。
- 同一场景内同一模板版本不重复添加。每个场景最多 100 条路径，超出容量时整批拒绝，不部分写入。
- 模板编号与版本存入 `source_code`，格式如 `TPL:AP-NETWORK-SERVICE@1`；路径具有独立的项目 ID 和显示编号。模板以后更新不会覆盖已经采用的内容。
- 报告中的项目路径编号和模板来源分列。存在模板路径时，普通风险评估表增加路径来源、攻击者、攻击向量；扩展攻击潜力表增加来源列。Excel 和 HTML 共用这套工作产品。
- 新增或编辑路径后，已有处置的评估依据会重新检查；工作人员应继续核对相关需求与验证证据。

## 开发接口

- `GET /api/v1/attack-path-templates`：读取本地模板目录，不联网、不修改项目。
- `GET /api/v1/workspaces/{id}/attack-path-templates?asset_id=...&property=...`：读取同一目录并附当前资产匹配线索，仍返回全部条目。项目成员权限照常生效。
- 目录版本为 `jieheng.attack-path-templates/1`，单条模板有稳定 `id` 和独立 `version`。评分只表示推荐匹配程度，和攻击可行性、项目风险值无关。
- 采用操作复用现有场景新增／更新接口，携带当前项目修订和幂等键。浏览和向表单添加模板都不持久化项目。

模板数据位于 `server/internal/assurance/attack_path_templates.go`；纯转换与去重位于 `client/src/attack-path-templates.js`。扩展目录时同时维护适用条件、版本和匹配测试，不从实体名称或画布位置猜测安全事实。

## 方法参考

组织方式参考公开的一手资料：[CAPEC 攻击模式方法](https://capec.mitre.org/about/index.html)、[CAPEC-94 通信中间人模式](https://capec.mitre.org/data/definitions/94.html)、[CAPEC-122 权限滥用](https://capec.mitre.org/data/definitions/122.html)、[CWE-294 认证重放](https://cwe.mitre.org/data/definitions/294.html)。模板内容为独立工程分析；项目评分应依据实际损害与攻击可行性确定。

## 从架构查找路径

在路径编辑器点击“从架构查找路径”，默认从外部实体搜索到关联资产所在实体，也可指定已建模的入口与目标。结果展示经过的实体、协议、跳数及是否为最短路线。采用后只填入当前表单，不立即写入项目。

- 沿数据流方向进行有界广度优先搜索；电能流、无效端点和重复节点不参与遍历。
- 连续相同协议合并后，同一入口、目标和协议序列保留首条最短路线；不同协议序列的绕行路线可以并列展示。相同长度的等价路线不保证全部返回。
- 最多搜索 12 跳、10,000 个状态并返回 20 个候选；达到界限时返回 `truncated: true`，不能据此断定不存在其他路径。
- 候选是连通关系草稿，需补充攻击动作、前提和协议转换条件并勾选确认，之后才能评定可行性。也可转为手工路径。
- 采用时保存引用的实体、数据流和语义指纹。相关实体或流语义变化后需重新检查；几何位置与线路布局变化不使确认失效。

`GET /api/v1/workspaces/{id}/attack-route-candidates?scenario_id=...&entry_id=...&target_id=...` 为只读接口。`scenario_id` 必填，入口与目标可省略，目标必须属于关联资产的实体。响应包含 `base_revision`、入口、目标、候选和截断状态，遵循项目读取权限并返回 ETag。

候选通过 `AttackPath.architecture_route` 保存到现有场景接口，字段为 `node_ids`、`flow_ids`、`fingerprint`、`reviewed`。客户端采用候选前应核对项目修订；服务端再次验证链路方向和指纹。它不生成漏洞证据，也不自动决定风险。
