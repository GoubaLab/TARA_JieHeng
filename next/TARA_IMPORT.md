# 中文 TARA 工作簿接入

当前适配器 `tara-chinese-v1` 对约定结构进行确定性读取。先创建空白项目，进入“TARA 工作产品”，选择 XLSX、检查预览，再导入。项目可以先有 DFD，但工作产品必须为空；先存 DFD 时使用 `asset_generation: catalog` 避免自动生成资产。错误会整体回滚，重复提交通过幂等键返回原结果。

## 支持的表结构

以下核心表的表头位于第 3 行，按列顺序识别：

| 表页 | 表头 |
| --- | --- |
| 资产与损害场景 | 资产编号、资产、类型、分组、关联功能、安全属性 |
| 威胁场景 | TS、威胁描述、攻击原因、STRIDE、受损属性、关联资产、关联DS、关联路径 |
| 攻击路径 | AP、TS、攻击者、向量、攻击步骤、ET、Ex、KoI、WoO、Eq、AP值、可行性 |
| 风险评估与处置 | TS、影响、可行性、初始风险、处置、控制措施、目标、CAL、残余可行性、残余风险、接受状态、处置说明 |
| 网络安全目标 | 目标编号、目标内容、关联TS、最高风险、CAL、控制主题 |
| 网络安全需求 | 需求编号、所属目标、需求内容、验证方法、分配专业、CAL、客户需求编号 |

损害行位于“资产与损害场景”，使用 DS-数字编号，列为编号、关联资产、功能、描述、相关方后果、安全属性、S、F、O、P、影响值、等级。其余核心编号前缀为 AS-、TS-、AP-、CSG-、CSR-；可引用多个编号。重复编号、缺失关系及孤立攻击路径会被拒绝。

“概述、方法与依据”须包含适配器识别的方法说明；“相关项定义”用于提取范围、边界和运行环境；“风险接受声明”保留原始接受条件与空白确认栏。其他表页不丢弃，全部成为只读来源快照。

## 方法和确认状态

此适配版本识别原始 SFOP 量表 0/10/100/1000，系数 S=1、F=1、O=0.1、P=0.1，影响下限 20/100/1000，任一单维严重时综合影响至少为重大。五因子攻击潜力按 10/14/20 下限由高可行性逐档降低。风险矩阵为 `[[1,1,2,3],[1,2,3,4],[2,3,4,5],[3,4,5,5]]`。未知方法需新增明确适配器，不能仅改表名冒充此模板。

解析后逐条复算损害影响、攻击潜力、场景风险与残余目标风险。计算不一致时返回 422，保留原方法和输入。该方法由工作簿模板定义；ISO/SAE 21434 不规定本模板的具体评分参数。

导入后方法仍待确认，空白负责人、客户确认和签署栏仍为空。残余风险为 `target`，完成需求验证后才可确认 `validated`。修改目标、需求或评估上下文使关联旧验证失效；几何布局变化不会使验证失效。

## 资源 API

所有路径以 `/api/v1` 开头，JSON 请求带 `X-Workspace-Client: jieheng`：

| 请求 | 用途 |
| --- | --- |
| `POST /workspaces/{id}/tara-import-previews` | 核对，不写修订 |
| `POST /workspaces/{id}/tara-imports` | 原子导入，需 `If-Match` 与 `Idempotency-Key` |
| `GET /workspaces/{id}/tara-imports/{resource_id}` | 读取来源表页、图像及核对信息 |
| `GET /workspaces/{id}/tara-imports/{resource_id}/source` | 下载字节一致的原始 XLSX |
| `POST /workspaces/{id}/damage-scenarios` | 创建损害场景 |
| `GET/PUT /workspaces/{id}/damage-scenarios/{resource_id}` | 读取、更新损害场景 |
| `POST /workspaces/{id}/security-goals` | 创建目标 |
| `GET/PUT /workspaces/{id}/security-goals/{resource_id}` | 读取、更新目标 |

导入请求为 `{filename, content_base64, asset_links?}`，其中可选映射为 `[{asset_id, node_ids}]`；映射目标必须是当前 DFD 中的有效端点。核心工作产品可编辑，原始表页不被编辑覆盖。

限制：原文件 1.4 MB、ZIP 展开 30 MB、40 个表页、每页 5,000 行 / 100 列。来源公式仅保留文本和缓存值，不执行；源文件作为本地归档保留。来源文件不会写入审计事件正文，事件只保存摘要与计数。公开仓库和发行包不包含真实工作簿、项目数据库或用户来源截图。

## 扩展与测试

新增版式时新增适配器与版本，明确列契约、编号、算法、状态和缺失数据行为，并使用原创合成工作簿测试成功导入、错误原子回滚、幂等重试与导出完整性。主要实现为 `server/internal/assurance/tara_import.go`，测试为 `tara_import_test.go`。不要把真实项目放进测试夹具。
