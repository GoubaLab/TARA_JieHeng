# 威胁建模产品工作流调研（2026-10-28）

本次只访问公开一手产品文档与开源项目，未访问或移用历史私有平台、规则或数据库。产品能力为官方文档已描述能力，并非商业平台实测结论。以下实现建议为本项目独立设计。

## 已核实的机制

| 产品 | 事实与一手来源 | 可借鉴的工作方式 |
| --- | --- | --- |
| IriusRisk | 规则处理组件、数据流、信任区与问卷上下文；版本历史及组件变化检测。[规则](https://www.iriusrisk.com/documentation/rules)、[版本与变化](https://www.iriusrisk.com/documentation/miscellaneous) | 少量结构化问题驱动解释明确的候选；更改架构后定向复核。 |

| OWASP pytm | 威胁规则与模型分离；规则读取属性、控制和边界关系，元数据供报告使用。[官方代码说明](https://github.com/OWASP/pytm) | 自有规则包版本化。其 Python eval 条件机制不移植，采用受限声明式匹配。 |
| CAIRIS | 资产、需求、威胁、漏洞、风险、文档证据通过元模型追溯，可限定运行环境。[追溯](https://docs.cairis.org/en/latest/traceability.html)、[风险模型](https://github.com/cairis-platform/cairis/blob/master/docs/risks.rst) | 知识采用带类型的证据关系，向量只是检索手段。 |

## 与本项目对应的独立改进建议

1. **P0 确定性自动分析**：项目已具备 DFD、自动资产、风险方法、基线和 AI 草案，但 automation.go 的历史接口已撤下。新增独立规则，使用实体、OS、通信和显式信任属性；展示命中事实、适用前提和需要检查的控制。未知控制不视为缺失，候选不等于漏洞结论。
2. **P0 自有证据链**：当前文档混合检索基础可复用；分别保存历史事件事实、漏洞公告、弱点、模式、威胁场景、措施、验证方法及来源版本。CVE 只能经产品、版本、配置、前置条件核实后认定适用，分析归纳与公告事实分开。
3. **P1 变更复核待办**：复用语义摘要、基线和审计；架构、规则或知识变化产生新增/修改/撤回/待复核清单，原有结论不覆盖。几何调整不造成分析失效。
4. **P1 模板与领域包**：原创 ECU、网关、云服务、充电与机器人模板带少量必答问题；21434 为汽车领域包。模板采用后固定版本，升级预览差异。
5. **P1 工程交付闭环**：优先内部责任人和待办，再可选工单接口。增加版本化模型交换与离线检查；门禁检查未处理风险、悬空引用、过期验证和未确认假设，所有外部回调幂等可恢复。

## 本轮规则实现约束

- 来源为独立工程分析，不复制上述产品规则、私有知识或描述。
- 输出规则 ID/版本、命中事实、前置条件、安全属性、可关联资产、待检查控制。
- 只复用准确关联且具备对应安全属性的现有资产；没有或存在歧义则阻止采纳。
- 安全属性表示保护需求，不意味着控制已经实施或缺失。
- 不推定任何 CVE 已适用，不生成风险或 CAL 分数，不自动确认处置或验证。
- 原生草案只补缺失损害、威胁/路径和待验证需求；现有人工记录不覆盖。
- 稳定候选 ID 和 source_code 用于幂等去重；计划哈希忽略坐标、端点、折线和标签位置。
- 当前节点没有显式边界归属字段，信任跨域只能来自外部实体类型或用户显式 trust_zone/信任域 属性。视觉矩形包含关系不得作为安全事实。

本轮已实现 P0 中的首版确定性规则与公开知识版本导入；变更复核待办、领域模板、模型文件交换及工单同步列为后续能力，不表示当前已支持。
