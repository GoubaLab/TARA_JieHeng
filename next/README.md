# 界衡 · 威胁建模平台

Go / SQLite 后端与 React / Ant Design 前端实现的独立本地工作台。以可追溯的工作产品组织范围、实体、资产、威胁、风险、处置、需求、验证和报告。汽车领域以 ISO/SAE 21434 为参考流程；支持通用产品、互联网、物联网、机器人与具身智能、充电设施的领域上下文。

## 构建与启动

在仓库根目录执行：

```sh
./next/tools/build-go.sh
npm ci --prefix next/client
npm run build --prefix next/client
./start.sh
```

打开 http://127.0.0.1:8790 。运行数据默认写入 `next/var/assurance.sqlite3`。可用 `./start.sh --database /绝对路径/assurance.sqlite3 --port 8790` 指定数据库与端口。源码仓库不附二进制与前端构建产物；服务仅监听本机回环地址。

后端要求 Go 1.25 或更新版本；其他平台应重新构建二进制。依赖版本由 go.mod/go.sum/package-lock.json 固定。正常运行不依赖 Python；`start.py` 仅为兼容启动器。

项目列表的“编辑信息”和项目总览的“项目基本信息”用于维护名称与说明，变更保留修订和审计记录。

## 建模与评估

1. **相关项与功能**：定义领域、边界、环境和假设，建立包含编号、名称及具体内容的功能目录。
2. **系统架构、资产识别**：建立实体和通信，识别资产及其安全属性；功能引用同时显示编号与内容。
3. **损害场景**：描述受影响对象、使用情景和不利后果，关联资产与功能。
4. **影响评级**：按 S/F/O/P 分别判断后果，查看 ISO/SAE 21434:2021 附录 F 分级释义及来源工作簿的项目准则，记录依据。
5. **威胁场景**：描述资产安全属性如何受损，关联已识别的损害场景。
6. **攻击路径**：填写实现威胁的步骤、入口、攻击者与前提，也可从预置模板建立草稿。
7. **攻击可行性**：逐条选择五因子档位或主要攻击向量，记录判定依据，由服务端计算等级。未完成的路径保持待评估。
8. **风险确定**：全部必要影响与可行性评估完成后，按项目方法计算风险。方法在项目设置中配置和确认。
9. **风险处置与需求、验证与报告**：记录处置、目标与残余风险，关联法规和安全需求，追加验证证据；核对交付检查并建立冻结基线。

界面按上述工作产品分步编辑，并允许返回修订。ISO/SAE 21434 的方法模块可以迭代组合；界面顺序不代表标准要求所有项目采用唯一顺序。评级准则释义用于辅助判断，不替代项目方法确认。
所有环节可以直接切换，待办由工作产品实时计算。「交付检查」集中显示缺口和下一步，支持还原点。企业内网模式提供账号、项目成员和角色权限；可选模型服务支持图片建模、全流程草案、质量复核和知识检索，采用前需人工检查。没有合格电子签名或自动审批。

模型服务配置与操作见 [辅助分析与模型服务](AI_ASSISTANCE.md)、[企业部署与备份恢复](ENTERPRISE_DEPLOYMENT.md)。

## 实体、OS 和通信

实体类型包括 ECU、外部实体、服务、通用设备、应用、云平台及参与者。OS 可记录家族、名称、版本、架构和备注，支持裸机、RTOS、Linux、QNX、Windows、Android、iOS、macOS 或自定义名称。默认实体视图将软件与数据存储收进实体内部。展开 DFD 允许处理过程与数据存储作为独立端点，便于保留零部件内部流向；模式切换会检查对象兼容性，不能静默丢弃结构。

数据流将传输方式、通信技术、范围、用途、上层协议和安全属性分开记录：

- 有线预置 FlexRay、CAN/CAN FD、DoIP、Ethernet、UART、JTAG、SWD/DAP、USB、LIN、SPI、I2C、RS-485。
- 无线预置 NFC、Wi-Fi、Bluetooth/BLE、UWB、RFID、Zigbee、Thread、LoRa、蜂窝通信；支持自定义技术。
- 近场、局域和广域是独立范围，不把所有无线都视为近场。用途可填写指令、请求、遥测等，不强制分成大量类别。
- 安全属性由评估人员明确选择，不从技术或用途自动推断安全性。

有线以实线、无线以虚线和方向箭头连接真实实体，Wi-Fi / NFC 等协议及无线图标直接显示在线路标签上。无线通信不会生成额外实体。所有连接共用避障布线：选中线路后拖动两端圆形手柄，在原实体四边切换接点；拖动线段上的方形手柄调整走向并吸附网格。“整理连线”清除手工途经点、保留连接边，“恢复自动”重新选择连接边。操作支持撤销、重做和 Esc 取消，保存后保留布局；布线空间不足会提示调整间距。标签默认位于路径长度中点，可拖动、恢复居中。静态 SVG 与画布使用相同路线及编号，不包含流动动画和编辑手柄。旧 protocol 识别仅供展示，确认分类后保存结构化值。

默认保存架构时自动生成并同步实体功能、内部软件、存储数据与传输数据的资产。重复保存不会重复建资产；人工修改、已有风险关系保留，移除图内来源后保留资产并提示复核。完整 TARA 导入项目使用 `catalog` 资产模式：保留原有资产及手工 DFD 关联，保存图形不再额外派生重复资产；旧客户端省略模式时也会保持当前配置。

“项目设置 → 编号规则”可分别设置实体、信任边界、软件、数据存储、数据流、资产、风险场景、攻击路径、安全需求及验证记录的前缀，支持分隔符和最少数字位数预览。显示编号与内部 ID 分离；调整格式保留原序号，删除后不复用，冻结报告保留当时规则。

画布方向动画可关闭，只表达方向，不表示时序或实时流量。静态 SVG 只导出图形，保留画布的图例样式、通道间距、方向和标签位置，按图形边界裁切；不附带属性或通信明细，不包含动画或脚本。完整属性仍在项目和报告中。HTML、JSON 和 Excel 报告均静态。浏览器会话内保存未提交画布草稿；保存后进入项目数据库。

旧处理节点和外部节点兼容显示为实体；旧独立存储需明确指定归属。归属时同步映射流端点和资产关系，产生自环或无效关系则整次拒绝，不自动丢弃连线。

## 项目设置

设置仅作用于当前项目，冻结基线保留当时的方法。

- SFOP 四维各 0–3；可取最高值，按相对权重计算平均值并向上取整，或使用系数直接求和。零权重维度不参与计算，总权重必须大于 0。
- 系数法不归一化、不取整：默认 `S×1 + F×1 + O×0.1 + P×0.1`，直接以 `SFOP总分 × 可行性` 计算风险分值，再按可配置阈值分为 1–5 级。系数、阈值和独立残余总分可保留小数。
- 另一种 `coefficient_bands` 方法先将四级映射到原始值（例如 0/10/100/1000），乘系数求和，再按三个下限阈值分档并查风险矩阵；可设置单维严重时的综合等级下限。它与“总分直接参与风险计算”的系数法独立，不能混用。
- 五因子攻击潜力采用附录 G 表 G.6 示例档位，ET、Ex、KoI、WoO、Eq 求和，再按项目的三个递增下限换算可行性。缺省下限为 14/20/25；导入项目保留自己的分档。主要攻击向量法使用表 G.9 示例映射。没有因子或未完成评级时不能自动认定为低风险。
- 可行性 1–4，越高越容易实现攻击。风险可用单调的 4 × 4 矩阵，或 `(影响 + 1) × 可行性` 后按四个递增阈值分成 1–5 级。
- 可配置维度显示名、影响级/可行性级/风险级的名称和判定条件。每条攻击路径独立计算，场景取最高风险，残余风险用同一分级算法。
- 必要评分、路径步骤或依据不完整时保持待评估，不把缺失值当作零。

默认方法是组织示例，不是 ISO/SAE 21434 强制算法。修改领域、实体 OS、通信语义、资产、评分方法或场景，会使受影响的原处置决策需要复核；几何布局和标签位置不影响评估摘要。纯默认字段补全保持旧摘要等价。需求变更使原验证证据失效，状态按最新记录判断。

## 完整 TARA 工作产品与导入

“TARA 工作产品”提供资产、独立损害场景、威胁场景、攻击路径、处置与接受条件、安全目标、安全需求及全部来源表页。支持多资产、多安全属性、多损害、多目标和多威胁追溯，保留业务编号、STRIDE、CAL、客户需求编号及攻击潜力因子。

在空白项目中选择 XLSX，先核对表头、引用、评估方法与初始/残余目标风险，再原子导入。当前支持明确的中文表结构 `tara-chinese-v1`，不是任意 Excel 自动识别器；原文件最大 1.4 MB。不一致会拒绝导入，不覆盖现有分析，也不会执行公式或宏。完整契约见 [导入说明](TARA_IMPORT.md)。

功能目录支持维护独立功能说明；仅有编号范围的来源内容会标为范围定义，不推断单个编号的专有含义。已有引用仍可追溯；新引用必须指向已定义功能。

核心工作产品可编辑；所有来源表页、嵌入图、公式文本与缓存值保留为只读快照，原始 Excel 可按字节原样下载。后续编辑不会改写来源文件。损害影响变化会重算关联威胁；多个损害按当前方法的实际影响值选最高者。

修改安全目标会更新关联处置中的目标文本，并要求重新评审。扩展 TARA 的验证记录同时绑定需求、关联目标与评估上下文；这些依据变化后，旧验证显示失效。未验证的残余风险是设计目标，只有全部关联需求具有当前有效通过记录才能确认为已验证；后续失败复测会撤销页面上的有效验证状态。客户确认和签署均由使用者实际完成，不自动代填。

## 参考资料与法规

企业知识中心支持按来源和版本维护资料，复核启用后用于检索与辅助分析。兼容参考目录默认未配置，批量选用入口不可用；已失效的引用保留状态占位，不能用于新增记录。引用状态变化不会自动改写项目正文或冻结基线。

法规目录位于 `data/regulations/`，按本地清单加载版本、条款和来源信息。源码仓库提供空清单；部署时按 [法规接入说明](data/regulations/README.md) 配置资料。应用校验内容摘要，不自动联网更新。目录可包含章节、条款、列项、表格行与说明；引用节点数量不等于独立合规要求数量。

每个法规版本独立记录来源、覆盖范围和原件定位。部分覆盖的资料标记为 `partial`；原始版本与修订版本分别保存，不隐式合并为现行全文。

条款可勾选到项目或需求，按原文来源查看。勾选引用不等于符合性判断，不自动生成评分或验证结论。

## 导出与交付

JSON 使用 `jieheng.work-products/1`；HTML 和 Excel 基础报告包含 17 类工作产品。扩展 TARA 项目追加 6 张追溯表及全部导入原表，因此表数为 23 + 来源表页数，包含方法依据、领域、OS、通信、风险与验证追溯。签批留空，未确认残余风险不代填。

Excel 由 Go 原生 Excelize 生成，无需额外的 JavaScript 运行时或 Office 安装。输出标准 `.xlsx`（OOXML），无宏、无执行公式；内容以文本单元格保存，防止输入被解释成公式。冻结标题行、中文列宽和说明批注便于复核。详见 [Excel 格式](EXCEL_EXPORT.md)。

```sh
(cd next/server && go test -race ./... && go vet ./...)
node --test next/tests/*.mjs next/tests/*.cjs
python3 next/tools/build-api-docs.py
python3 next/tools/test_public_release.py
```

公开源码发布由 `tools/public_release.py` 按文件白名单生成暂存目录，并检查路径、内容指纹和文件摘要。运行数据库、备份、缓存及项目资料不纳入发布范围。

API 采用 `/api/v1` 资源路径、修订条件与幂等写入，详见 [接口约定](API_CONVENTIONS.md) 和 [OpenAPI](server/openapi.json)。领域模型和模块见 [架构说明](ARCHITECTURE.md)，流程、评分算法、自有资料和报告扩展见 [二次开发指南](EXTENDING.md)。当前没有运行时插件或动态流程设计器；增加步骤和任意维度需按指南修改源码。

## 确定性分析与公开知识

「自动分析」提供 8 条内置规则，在不调用模型的情况下生成可审阅的候选和原生工作产品。企业知识支持公开案例包导入、逐条复核启用、同源版本替换以及 CISA KEV 增量收集。初始案例记录公开 CVE 事实、适用条件、工程分析和来源链接。见 [自动分析](AUTOMATION.md)、[知识积累](PUBLIC_KNOWLEDGE.md) 和 [产品调研](PRODUCT_RESEARCH.md)。

## 攻击路径模板

“攻击路径”步骤支持从 16 类预置模板添加路径，按分类/关键词选择并查看资产匹配线索。模板采用后可编辑，评分保持待评估，保存场景时保留模板版本。使用与扩展见 [攻击路径模板](ATTACK_PATH_TEMPLATES.md)。
